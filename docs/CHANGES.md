# Переход из исследования в MVP — полный разбор правок

**Дата:** 10 августа 2026
**Задача:** сделать рабочий первый экран, вырезать генерацию ответа моделью,
проверить безопасность и сохранность данных, подготовить к деплою.

Документ построен по схеме **Причина → Что сделано → Следствие**. Разделы
идут по темам; поимённый индекс всех затронутых файлов — в конце.

---

## 0. Исходное состояние

Проект был исследованием ретривала: три реализации поиска (dense / BM25 /
гибрид через RRF), корпус из 29 договоров аренды, разобранный в 1299 чанков с
768-мерными эмбеддингами. Поверх стоял роут `/api/chat`, который склеивал
найденные фрагменты в промпт и отдавал их в `gpt-4.1`.

Фронтенда не было: `app/page.tsx` возвращал `<></>`. Запускалось всё через
`lib/test/eval.ts` вручную из терминала.

Три факта, которые определили объём работ:

| Факт | Как обнаружен |
| --- | --- |
| `tsc --noEmit` давал **24 ошибки** — сборка Next упала бы | `npx tsc --noEmit` |
| Индекс на 21 МБ читался и парсился **дважды** | чтение `search.ts:6` и `bm25.ts:6` |
| `embed.ts` писал в несуществующий каталог | `find app -type f` — каталога `app/api/docs` нет |

## 1. Вырезание генерации

### 1.1 Удалён роут `/api/chat`

**Причина.** Прямой запрос: генерация — самая дорогая часть, а исследованием
был ретривал, не обёртка над ним. Плюс `generateText` с `gpt-4.1` — это
единственное место, где стоимость запроса измерялась центами, а не долями
цента.

**Что сделано.** Каталог `app/api/chat` удалён целиком. Копия старого файла
сохранена вне репозитория (`…/scratchpad/chat-route.ts.bak`) на случай, если
понадобится вернуть логику.

**Следствие.**

- Вызовов `generateText` в проекте не осталось ни одного.
- Заодно исчезла **prompt injection**: раньше текст договоров склеивался в
  промпт без разделителей и без запрета исполнять инструкции из контекста.
  Сейчас текст документов не попадает ни в одну модель — инъекции некуда
  приземлиться.
- Убран неиспользуемый импорт `embed` (был в `route.ts:2`).
- Пропала возможность «спросить вопрос и получить ответ». Это осознанный
  размен: MVP показывает найденные фрагменты, а не сгенерированный ответ.

### 1.2 Эмбеддинг запроса оставлен

**Причина.** Резать вызовы OpenAI полностью означало бы выкинуть dense и
hybrid — то есть ровно то, ради чего исследование делалось.

**Что сделано.** `text-embedding-3-small` (768 измерений) остался в
`lib/api/search.ts` для векторизации поискового запроса.

**Следствие.** Один запрос ≈ 20 токенов ≈ **$0.0000004**. Миллион запросов —
меньше доллара. Режим `bm25` сети не касается вообще и работает без ключа.

## 2. Безопасность HTTP-эндпоинта

Новый роут: `app/api/search/route.ts`.

### 2.1 Валидация входа

**Причина.** Старый код был одной строкой: `const { question } = await
req.json()`. Отсюда три дыры:

- невалидный JSON → необработанное исключение → 500 со стектрейсом;
- `question` отсутствует или не строка → уходит в провайдера как есть;
- строка на мегабайт → счёт за токены, оплачивает владелец ключа.

**Что сделано.** Проверяются все поля до того, как что-либо уйдёт в поиск:

| Поле | Правило | Ответ при нарушении |
| --- | --- | --- |
| тело | парсится как JSON, является объектом | 400 |
| `query` | строка, после `trim()` 1–300 символов | 400 |
| `mode` | `dense` \| `bm25` \| `hybrid`, по умолчанию `hybrid` | 400 |
| `k` | целое 1–10, по умолчанию 5 | 400 |

**Следствие.** Проверено на девяти вариантах плохого ввода — везде 400 с
понятным текстом вместо 500:

```
невалидный JSON      → 400 Тело запроса должно быть корректным JSON
query отсутствует    → 400 Поле query должно быть строкой
query = 123          → 400 Поле query должно быть строкой
query = "   "        → 400 Поле query не должно быть пустым
query 301 символ     → 400 Запрос длиннее 300 символов
mode = "gpt4"        → 400 Поле mode должно быть одним из: dense,bm25,hybrid
k = 999              → 400 Поле k должно быть целым числом от 1 до 10
k = 2.5              → 400 Поле k должно быть целым числом от 1 до 10
тело = [1,2,3]       → 400 Поле query должно быть строкой
```

Потолок в 300 символов ограничивает и стоимость: длиннее запрос физически
не отправить.

### 2.2 Ограничение частоты запросов

**Причина.** Без лимита развёрнутый эндпоинт — открытый прокси к чужому
OpenAI-ключу. Даже при цене $0.0000004 за запрос скрипт в цикле создаёт
неограниченную нагрузку на инстанс.

**Что сделано.** `lib/api/rate-limit.ts` — скользящее окно: **20 запросов в
минуту** на IP (`x-forwarded-for`, первый адрес в списке). Превышение → 429 с
заголовком `Retry-After`. `Map` чистится от протухших ключей при переходе
через 5000 записей, чтобы не расти бесконечно.

**Следствие.** Проверено: 21-й запрос за минуту получает
`429 Too Many Requests` и `retry-after: 39`.

**Ограничение, о котором важно знать.** Счётчик живёт в памяти процесса. На
serverless у каждого инстанса своя копия, поэтому фактический лимит =
20 × число инстансов. Для MVP этого достаточно — цель отсечь цикл в скрипте,
а не выдержать DDoS. Интерфейс (`rateLimit(key)`) специально сделан таким,
чтобы замена на Upstash / Vercel KV не потребовала правок в роуте.

### 2.3 Ошибки без внутренних деталей

**Причина.** Необработанное исключение в Next отдаёт наружу стектрейс, а он
раскрывает пути файловой системы и структуру проекта.

**Что сделано.** Поиск обёрнут в `try/catch`: подробности уходят в
`console.error`, клиенту возвращается `500 { error: "Поиск не удался" }`.

**Следствие.** Диагностика остаётся в логах сервера, наружу не утекает
ничего о внутреннем устройстве.

## 3. Утечки в теле ответа

### 3.1 Векторы больше не уходят клиенту

**Причина.** `search()` возвращала `{ ...chunk, score }`, а `chunk` содержит
поле `embedding` — 768 чисел. Старый роут спасало только то, что он брал
из результата лишь `.text` и `.file`. Любой новый потребитель получил бы
векторы целиком.

Замерено на реальных данных:

| | Размер |
| --- | --- |
| чанк с вектором | 16.4 КБ |
| чанк без вектора | 2.3 КБ |
| **лишнего на 5 результатов** | **70 КБ** |

**Что сделано.** Функция `toHit()` в `lib/api/store.ts` перечисляет поля
явно — `text`, `paragraphIds`, `file`, `score` — вместо spread.

**Следствие.** Ответ похудел на 70 КБ. Важнее другое: список стал
*белым*, а не чёрным — новое поле, добавленное в тип `Chunk`, не утечёт
наружу автоматически. Проверено: `'embedding' in results[0]` → `false`.

### 3.2 Имена файлов заменены на человекочитаемые

**Причина.** Ответ содержал `a.doaHDzg8N.s12EpndLImz58WrW-lease_427.plain.html`
— внутренний идентификатор из хранилища. Клиенту он не нужен, а наружу
раскрывает схему именования.

**Что сделано.** `docLabel()` в `lib/api/store.ts` отрезает префикс до первого
дефиса и суффикс `.plain.html`. Перед этим проверено, что во всех 29 именах
ровно один дефис — обрезка не срежет лишнего.

**Следствие.** Наружу уходит `lease_427`. Поле `file` из ответа API убрано
совсем — в JSON остаётся только `doc`. Проверено: `'file' in results[0]` →
`false`.

## 4. Работа с индексом

### 4.1 Один разбор вместо двух

**Причина.** `search.ts:6` и `bm25.ts:6` независимо делали
`fs.readFileSync("lib/data/embed/embeddings.json")` **на уровне модуля**. Один
и тот же файл на 21 МБ читался с диска и парсился дважды, а в памяти
оказывались две независимые копии массива из 1299 чанков с векторами.

**Что сделано.** `lib/api/store.ts` — единая точка доступа `getIndex()` с
ленивой мемоизацией (`cached ??= JSON.parse(...)`).

**Следствие.** Один разбор на процесс, одна копия в памяти. Разбор
откладывается до первого обращения: импорт модуля больше ничего не читает
с диска.

### 4.2 BM25-индекс строится лениво

**Причина.** `bm25.ts` вызывал `engine.addDoc()` для каждого из 1299
документов и `engine.consolidate()` прямо при импорте модуля. Эта работа
выполнялась даже когда пользователь запрашивал только dense.

**Что сделано.** Построение вынесено в `getEngine()`, вызывается при первом
обращении к `bm25Search()`.

**Следствие.** Холодный старт в режиме dense больше не платит за
стемминг и индексацию 1299 документов. При первом BM25-запросе цена
платится один раз, дальше движок переиспользуется.

### 4.3 Меньше копирований при dense-поиске

**Причина.** Старый код делал `indexed.map((chunk) => ({ ...chunk, score }))`
— то есть создавал 1299 полных копий чанков **вместе с векторами**, чтобы
затем отсортировать и выбросить все, кроме пяти.

**Что сделано.** Сначала считается лёгкий массив пар `{ i, score }`,
сортируется, обрезается до `k`, и только потом `k` элементов превращаются
в `Hit`.

**Следствие.** Вместо 1299 копий по 16.4 КБ — 1299 маленьких объектов из
двух чисел и 5 финальных копий.

## 5. Безопасность записи на диск

Это тот раздел, ради которого задавался вопрос «ничего не пропадёт?».

### 5.1 Что было проверено про сохранность

**Причина.** Нужно было доказать, а не предположить, что запуск скриптов не
уничтожит 21 МБ эмбеддингов и 29 исходных HTML.

**Что сделано.** Полный поиск всех операций записи по исходникам:

```
grep -rnE 'writeFileSync|appendFileSync|mkdirSync|rmSync|unlinkSync|rename|truncate|createWriteStream' lib app --include='*.ts'
```

Нашлось ровно три места — `parse.ts:59`, `parse.ts:60`, `embed.ts:26`. Ни
одно не входит в граф импортов `eval.ts` (`eval → search / bm25 / hybrid →
cosine`, все только читают). Дополнительно снят слепок `mtime` всех 39 файлов
в `lib/` до и после прогона — ни один не изменился.

**Следствие.** Ответ на исходный вопрос: **`eval.ts` данные не трогает**. Это
проверенный факт, а не оценка.

### 5.2 Починены пути записи в `embed.ts`

**Причина.** Скрипт писал результат в `app/api/docs/data/embeddings.json`.
Такого каталога в проекте нет, поэтому `writeFileSync` падал с `ENOENT`
**после** того, как все эмбеддинги были посчитаны. И даже при удачной записи
результат оказался бы не там: `search.ts`, `bm25.ts` и `lens.ts` читают
`lib/data/embed/embeddings.json`.

**Что сделано.** Путь исправлен на тот, откуда читают. Чтение входного
`chunks.json` переведено на `process.cwd()`, чтобы не зависеть от каталога
запуска.

**Следствие.** Скрипт стал рабочим. Но теперь он способен перезаписать
настоящий индекс — что напрямую ведёт к следующему пункту.

### 5.3 Атомарная запись

**Причина.** `fs.writeFileSync` сначала обрезает целевой файл до нуля, и
только потом пишет. Для 21 МБ это заметное окно: `Ctrl+C`, падение процесса
или ошибка сети посреди записи оставляют **битый файл без резервной копии**.
Git в проекте не инициализирован, откатиться неоткуда.

**Что сделано.** `lib/data/atomic.ts` — `writeJsonAtomic()`: запись во
временный файл рядом с целевым, затем `fs.renameSync`. В пределах одной
файловой системы `rename` атомарен. При ошибке временный файл удаляется, и
исключение пробрасывается наверх.

**Следствие.** Промежуточного состояния не бывает: на диске либо целиком
старое содержимое, либо целиком новое. Оба скрипта — `parse.ts` и `embed.ts`
— пишут через эту функцию.

### 5.4 Защита от рассинхрона векторов и чанков

**Причина.** В `embed.ts` векторы сшиваются с чанками **по индексу массива**:
`chunks.map((c, i) => ({ ...c, embedding: all[i] }))`. Если провайдер вернёт
на каком-то батче меньше векторов, чем было отправлено, каждый последующий
чанк получит чужой вектор. Ошибки не будет — поиск просто начнёт молча
возвращать текст, не соответствующий вектору. Это худший вид поломки:
незаметный.

**Что сделано.** Перед записью — жёсткая проверка
`all.length !== chunks.length` с падением и понятным сообщением. Плюс
прогресс по батчам в консоль. И `parse.ts`, и `embed.ts` получили комментарии
о том, что запускать их надо парой и в определённом порядке.

**Следствие.** Рассинхрон теперь роняет скрипт до записи, а не портит индекс
тихо.

### 5.5 Починены пути чтения в `parse.ts`

**Причина.** Скрипт читал `./pool` и писал `data/chunks.json` — оба пути
относительно текущего каталога. Из корня репозитория первый путь не
существует; из `lib/data` — создавался бы `lib/data/data/chunks.json`, то есть
не там, где `embed.ts` ожидает вход.

**Что сделано.** Пути привязаны к `process.cwd()` и приведены в соответствие
с `embed.ts`: читаем `lib/data/pool`, пишем `lib/data/embed/chunks.json`.

**Следствие.** Оба скрипта теперь работают из корня репозитория и передают
данные друг другу по одному и тому же пути.

### 5.6 Абзацы без `id` отбрасываются

**Причина.** `$(el).attr("id")` возвращает `string | undefined`, но тип
`Paragraph` объявлял `id: string`. Ошибка типов (`TS2345`), а по сути — абзац
без `id` попал бы в `paragraphIds` как `undefined` и сломал бы ссылку на
источник в результатах поиска.

**Что сделано.** Фильтр с type predicate: `p.id !== undefined && p.text.length
>= 40`.

**Следствие.** В чанки попадают только абзацы, на которые можно сослаться.

## 6. Типы и сборка

### 6.1 24 ошибки типов → 0

**Причина.** `npx tsc --noEmit` падал с 24 ошибками — все существовали до
начала работ. Next запускает проверку типов на этапе `build`, то есть
**деплой был невозможен в принципе**, хотя локально `next dev` работал.

Разбивка:

| Тип ошибки | Кол-во | Где |
| --- | --- | --- |
| `TS5097` — импорт с расширением `.ts` | 8 | `bm25` 1, `hybrid` 2, `search` 2, `eval` 3 |
| `TS7006` — неявный `any` в параметрах | 13 | `hybrid` 5, `embed` 3, `eval` 4, `lens` 1 |
| `TS7016` — нет типов у пакета | 2 | оба wink-пакета |
| `TS2345` — `string \| undefined` vs `string` | 1 | `parse.ts:25` |

**Что сделано.**

1. **`allowImportingTsExtensions: true`** в `tsconfig.json`. Расширения `.ts`
   в импортах нужны, чтобы файлы запускались голым `node` (нативное срезание
   типов). Опция требует `noEmit: true` — он уже стоял.
2. **`types/wink.d.ts`** — ambient-декларации для `wink-bm25-text-search` и
   `wink-nlp-utils`. У обоих нет ни собственных типов, ни пакетов `@types`.
   Описаны только реально используемые методы.
3. Типизированы `rrf()` в `hybrid.ts`, `show()` в `eval.ts`, callback'и в
   `embed.ts` и `lens.ts`.
4. Исправлен `parse.ts` (см. 5.6).

**Следствие.** `npx tsc --noEmit` — чисто. `npm run build` проходит. Появился
скрипт `npm run typecheck`, чтобы это можно было проверять без полной сборки.

Побочный выигрыш: типы `Chunk` и `Hit` из `store.ts` теперь связывают все три
режима поиска. `hybridSearch` больше не принимает `any` — если сигнатура
`search()` изменится, `rrf()` перестанет компилироваться.

### 6.2 Устаревший API AI SDK

**Причина.** `openai.textEmbeddingModel()` помечен `@deprecated` в
`@ai-sdk/openai` 4.0.34: «Use `embeddingModel` instead».

**Что сделано.** Замена на `openai.embeddingModel()` в `search.ts` и
`embed.ts`. Тип возврата идентичен (`EmbeddingModelV4`), поведение не
меняется.

**Следствие.** Код переживёт мажорное обновление SDK, где deprecated-алиас
уберут.

### 6.3 Устаревший тип события React

**Причина.** В `@types/react` 19 тип `FormEvent` помечен `@deprecated` с
формулировкой «FormEvent doesn't actually exist».

**Что сделано.** Обработчик `onSubmit` типизирован как
`SubmitEvent<HTMLFormElement>` — тип, который React 19 действительно
передаёт (`onSubmit?: SubmitEventHandler<T>`).

**Следствие.** Предупреждений нет, тип соответствует реальному событию.

## 7. Первый экран

Файл `app/page.tsx` — раньше `return <></>`.

**Причина.** Исследование запускалось только из терминала через `eval.ts`.
Посмотреть, как режимы ведут себя на произвольном запросе, было нельзя.

**Что сделано.** Клиентский компонент:

- поле ввода с `maxLength={300}` (зеркалит серверный лимит);
- переключатель `Dense / BM25 / Hybrid` — радиогруппа внутри `<fieldset>`
  с `<legend class="sr-only">`, сами `<input type="radio">` визуально скрыты,
  но остаются в дереве доступности;
- подпись под переключателем поясняет выбранный режим;
- состояния: загрузка (`Ищу…`, кнопка заблокирована), ошибка, пустой
  результат;
- карточки результатов: номер, документ, диапазон абзацев моноширинным,
  score справа, текст с `line-clamp-6`.

**Следствие.** `eval.ts`, превращённый в экран. Видно, где dense выигрывает у
BM25 и что даёт их слияние — это и был предмет исследования. Проверено в
браузере: запрос `notice period for early termination` в режиме hybrid
возвращает 5 фрагментов с корректными метаданными.

### 7.1 Тёмная тема

**Причина.** `globals.css` объявлял `--background: #ffffff` без варианта для
тёмной темы. При системной тёмной теме страница светила белым.

**Что сделано.** Блок `@media (prefers-color-scheme: dark)` с переопределением
токенов; в разметке использованы парные классы `dark:`.

**Следствие.** Страница корректна в обеих темах (проверено скриншотом в
тёмной).

### 7.2 Исправлен шрифт

**Причина.** `globals.css` задавал `body { font-family: Arial, Helvetica,
sans-serif }` — это перебивало шрифт Geist, который `layout.tsx` подключал
через `next/font` и CSS-переменную. Наследие шаблона `create-next-app`.

**Что сделано.** `font-family: var(--font-geist-sans), system-ui, sans-serif`.

**Следствие.** Подключённый шрифт наконец применяется.

### 7.3 Метаданные страницы

**Причина.** В `layout.tsx` оставались заглушки `title: "Create Next App"`,
`description: "Generated by create next app"`.

**Что сделано.** Заменены на осмысленные.

**Следствие.** Вкладка браузера и превью ссылки показывают, что это за проект.

## 8. Готовность к деплою

### 8.1 Трассировка файла индекса

**Причина.** Самая коварная из найденных проблем. `embeddings.json` читается
через `fs`, а не импортируется — значит, статический анализ Next его не
видит и **не кладёт в бандл serverless-функции**. Локально всё работает
(файл лежит на диске), на Vercel `/api/search` падает на первом же запросе.

**Что сделано.** В `next.config.ts`:

```ts
outputFileTracingIncludes: {
  "/api/search": ["./lib/data/embed/embeddings.json"],
}
```

**Следствие.** Проверено, что ключ маршрута указан верно — Next молча
игнорирует несовпадающие ключи, поэтому опечатка выглядела бы точно так же,
как рабочая настройка. После сборки:

```
.next/server/app/api/search/route.js.nft.json
  → ../../../../../lib/data/embed/embeddings.json  (существует, 20.9 МиБ)
```

### 8.2 Предупреждение в `.gitignore`

**Причина.** 21 МБ сгенерированного JSON в репозитории выглядит как мусор,
который хочется добавить в `.gitignore`. Но без него сборка не сможет
затрассировать файл, и прод сломается — при том что локально всё продолжит
работать. Ловушка для будущего «наведения порядка».

**Что сделано.** Комментарий в `.gitignore` рядом с блоком `.env*`,
объясняющий, почему `lib/data/embed/*.json` там быть не должно.

**Следствие.** Правило зафиксировано там, где его прочитают в нужный момент.

### 8.3 Явное указание рантайма

**Причина.** Роут использует `fs` и держит в памяти 21 МБ — это несовместимо
с Edge Runtime.

**Что сделано.** `export const runtime = "nodejs"` в
`app/api/search/route.ts`.

**Следствие.** Роут не переедет на Edge при смене умолчаний.

## 9. Скрипты и документация

**Причина.** Запуск скриптов зависел от текущего каталога и от того,
подставлен ли `.env`. Голый `node` **не читает `.env`** — проверено:
`node -e "console.log(!!process.env.OPENAI_API_KEY)"` печатает `false`, а с
`--env-file=.env` — `true`. Это неочевидно, потому что Next подставляет `.env`
сам, и в дев-режиме всё работает.

**Что сделано.** Добавлены npm-скрипты с правильными флагами:

| Скрипт | Команда | Назначение |
| --- | --- | --- |
| `typecheck` | `tsc --noEmit` | проверка типов без сборки |
| `data:parse` | `node lib/data/parse.ts` | HTML → `chunks.json` |
| `data:embed` | `node --env-file=.env lib/data/embed.ts` | `chunks.json` → `embeddings.json` |
| `eval` | `node --env-file=.env lib/test/eval.ts` | качество ретривала |

`README.md` переписан: режимы, контракт API, порядок пересборки индекса,
деплой-чеклист. В `eval.ts` добавлен комментарий с командой запуска и
пометкой, что скрипт только читает.

**Следствие.** Не нужно помнить про `--env-file` и рабочий каталог.
